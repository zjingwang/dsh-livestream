# 二开改进路线图（聚焦 B 站单平台）

> 目标：在保持上游"大脑/身体分离、DSH 插件、B 站直播"核心架构不变的前提下，把 AI 主播做得"更像真人"。
> 多平台（抖音/快手）已暂缓（抖音需 1000 粉才能 PC 直播、AI 无人直播封号风险高），不排期。
> 所有改动遵循 [AGENTS.md](../AGENTS.md)：通过 `check` + `test`，过 CI，提交符合 Conventional Commits，提交前自查敏感信息。

## 原则

1. **先铺地基再盖楼**：舞台动作协议是后面所有"能动真格"功能的地基，最先做。
2. **AI 能做事，观众看得见**：每个功能都包含"AI 动作" + "舞台/直播间呈现"两个半场。
3. **小步交付**：每项做完都能本地彩排验证，再进主线。
4. **不碰角色素材**：大肥鱼素材（CC BY-NC-SA）只做使用，不修改/替换。

## 各改进项详情

### P0-1 舞台动作协议（2026-11-07）
把舞台渲染协议从"视频+字幕+表情"抽象为**动作事件流**：`play_audio` / `play_video` / `set_scene` / `play_sfx` / `show_banner` / `set_progress` 等。
- 现状：stage server / stage 页只支持视频、字幕、表情，每个新功能都要改渲染器。
- 完成后：新功能 = 加一种动作类型，舞台侧一次实现，后续 #2/#8/#9 全部挂在这上面。
- 交付：协议类型定义 + stage server 分发 + 舞台页渲染 + 控制台调试面板 + 单测。

### P0-2 点歌系统（2026-11-21，依赖 #1）
观众弹幕点歌 → AI 确认 → 排队播放 → 舞台点歌栏显示歌名/点歌人。
- `biliMusic` 工具：搜歌/播放/停止（音频通道，说话自动降音量，复用现有混音逻辑）。
- `orders` 通用队列改造：从游戏专用抽成通用点单（点歌/点菜/任意），支持切歌、顶歌、同人限点、队列上限。
- 舞台音乐播放器：歌名、进度、封面；点歌栏 UI。
- 交付：端到端链路（弹幕→AI→播放→呈现）+ 本地彩排验证 + 单测。

### P0-3 打断策略（2026-11-14）
真人主播的"控场"：刷屏时主动切话题（"我们看看别人说什么"）、大礼物打断当前话题、冷场找话增强。
- 在 `core/attention` 打分基础上增加**抢占/打断规则**，而不是纯排队。
- 交付：规则可配置（config 里开关与阈值）+ 单测 + 彩排脚本验证。

### P1-4 事件记忆回旋镖（2026-11-28）
把"说过的事"也记下来，隔场兑现/回cue：昨天答应唱的歌今天主动唱、观众提到的梗在合适时机 Call back。
- `core/memory` 扩展"事件记忆"维度（与观众记忆库分开，跨场持久化）。
- 交付：事件记忆模型 + 提取与回cue的 agent 提示 + 单测。

### P1-5 情绪状态机（2026-12-05）
连续被怼会"来气"、被夸会开心，情绪**持久**影响语速/表情/回怼力度，而不是每条弹幕独立反应。
- 情绪状态（心情值）挂在 persona 上，随事件增减、随冷场回落。
- 交付：情绪模型 + 对表情/台词生成的影响 + 单测。

### P1-6 可控的不完美（2026-12-05，随 #5）
偶尔"没听清"让观众重说、念错名字自嘲。真人感的关键是合理的小瑕疵，AI 太完美反而不像人。
- 交付：低概率触发 + 台词模板 + 彩排验证。

### P1-7 事故圆场（2026-12-12）
接 OBS/推流状态感知：卡了、断了、声音异常，AI 主动圆场（"刚卡了一下你们看到吗"），比真人还稳。
- `body` 接入 OBS 状态回调 + 断流检测，映射成事件喂给 attention。
- 交付：状态检测 + 圆场台词 + 彩排模拟验证。

### P2-8/9 音效、BGM 与场景切换（2026-12-19 / 2027-01-09，依赖 #1）
掌声/笑声/叮等音效按事件触发；开播 BGM、冷场换氛围曲；闲聊/放视频/游戏/谢幕的"场景"自动切换。
- 交付：SFX 通道 + 场景状态机 + 舞台呈现 + 彩排验证。

### P2-10 伪连麦（2027-01-23）
观众"上麦"（文字/语音条），AI 念出来 + 当面回应，真人感最强的一招。
- 交付：上麦流程 + 呈现 + 彩排验证。

### P2-11 弹幕小游戏/抽奖竞猜（2027-02 评估）
抽奖、竞猜、骰子/转盘、"今天播什么观众投票"。先观察 #1-#7 效果与人气再排具体玩法。
